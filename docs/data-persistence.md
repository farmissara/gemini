# ขอบเขตการจัดเก็บข้อมูล

เอกสารนี้สรุปการจัดเก็บข้อมูลตามโค้ดปัจจุบัน การบันทึกบน Supabase จะทำงานได้เมื่อโปรเจกต์ที่แอปเชื่อมต่อมี migration ที่เกี่ยวข้องครบแล้ว

| ข้อมูล/ฟีเจอร์ | จัดเก็บที่ใด | ขอบเขตและข้อควรทราบ |
| --- | --- | --- |
| โรงเรียน โปรไฟล์ นักเรียน ครู วิชา คะแนน เช็กชื่อ ใบแจ้งหนี้ ประกาศ ตารางสอน คาบเรียน และใบลา | Supabase | จำกัดการเข้าถึงตามโรงเรียนและบทบาทด้วยนโยบายฐานข้อมูล บางส่วนมีสำเนาข้อมูลล่าสุดในเบราว์เซอร์เพื่อเปิดดูเมื่อออฟไลน์ |
| งานที่สั่ง การส่งการบ้าน บทเรียน LMS และสถานะเรียนจบ | Supabase | ต้องติดตั้ง migration ของงาน/การบ้านและ LMS |
| แฟ้มข้อมูลนักเรียน พฤติกรรม SDQ ห้องพยาบาล ข้อมูลวิทยาเขต และข้อมูลเชิงคุณภาพ MOE | Supabase | ต้องติดตั้ง migration ของ student records และ campus/MOE |
| คิวงานออฟไลน์และข้อมูลโรงเรียนล่าสุด | เบราว์เซอร์ (`localStorage` และ IndexedDB) | เป็นสำเนาช่วยทำงานบนอุปกรณ์ ไม่ใช่ backup บน cloud และอาจหายเมื่อเคลียร์ข้อมูลเบราว์เซอร์ อุปกรณ์จึงมีข้อมูลนักเรียนที่ต้องดูแลให้ปลอดภัย |
| คีย์ AI ของโรงเรียน | ตาราง secret ที่เข้ารหัสใน Supabase | ต้องตั้ง `SCHOOL_AI_ENCRYPTION_KEY`; ไม่รวมคีย์ในไฟล์สำรอง หากย้ายระบบหรือกู้คืนและต้องใช้ AI ต้องตั้งคีย์ใหม่ |
| ไฟล์สำรอง | ดาวน์โหลดลงเครื่องผู้ดูแล | ไฟล์ใหม่เข้ารหัสในเบราว์เซอร์ด้วย passphrase; ระบบไม่เก็บ passphrase หากลืมจะกู้ไฟล์ไม่ได้ ไฟล์ JSON รุ่นเก่าที่ยังไม่เข้ารหัสยังนำเข้าได้ การสำรองเป็นแบบสั่งเอง ไม่อัปโหลดไป Google Drive และไม่มีรอบสำรองอัตโนมัติ |
| เกม/ความคืบหน้าและโมดูลที่ยังไม่มีตารางรองรับ | แตกต่างกันไป หรืออาจเก็บเฉพาะในเครื่อง | อย่าสรุปว่าทุกฟีเจอร์ที่เห็นในหน้าเว็บถูกบันทึกลง Supabase ให้ทดลองบันทึกแล้วเปิดจากอีกเบราว์เซอร์ก่อนใช้งานจริง |
| การชำระเงินจริงและการส่ง LINE แบบ production | ผู้ให้บริการภายนอกยังเชื่อมไม่ครบ | การสร้างใบแจ้งหนี้/QR หรือการกดปุ่มใน UI ไม่ได้ยืนยันว่าเงินเข้า หรือข้อความถูกส่งถึงผู้รับ |

## ขอบเขตไฟล์สำรอง

ไฟล์สำรองประกอบด้วยเฉพาะตารางที่ backup API รองรับและ Storage bucket ที่กำหนดไว้ รหัสผ่านบัญชี, push subscription ของอุปกรณ์ และ AI secrets ไม่รวมอยู่ในไฟล์ การกู้คืนผ่านการตรวจสอบก่อน และเป็นการเพิ่ม/ปรับปรุงข้อมูล ไม่ลบแถวที่ไม่มีในไฟล์ การ export สำเร็จจึงยังไม่ใช่หลักฐานว่ากู้คืนได้ครบ ควรซ้อม restore กับ Supabase staging

โหมดซ้อมกู้คืนเปิดได้เฉพาะเซิร์ฟเวอร์ Staging ที่ตั้ง `BACKUP_RESTORE_ENVIRONMENT=staging` และใช้ Supabase project แยกจากต้นทางเท่านั้น ระบบตรวจสิทธิ์ ขอบเขต ตาราง/Storage และ checksum ก่อนแสดงรายการข้อมูลรวมถึงรายการที่ไม่อยู่ในไฟล์ แล้วจึงให้ Super Admin ยืนยันการนำเข้าแบบ merge บน Staging การซ้อมไม่สร้างบัญชี Auth หรือรหัสผ่านให้; Staging ควรมี migration และบัญชีที่ต้องใช้ตรงกับข้อมูลก่อนทดสอบ และควรเป็น environment แยกที่ทิ้งได้

## วิธีตรวจว่าข้อมูล persist จริง

1. ใช้ Supabase local หรือ staging ที่ติดตั้ง migration ครบ
2. สร้าง/แก้ข้อมูลในโมดูลที่ต้องการ แล้วตรวจว่ามีแถวในตาราง Supabase ที่คาดไว้
3. reload และเปิดบัญชีเดียวกันจากเบราว์เซอร์หรืออุปกรณ์อีกเครื่อง เพื่อแยกข้อมูล cloud ออกจาก cache ในเครื่อง
4. เมื่อแก้ระบบสำรอง ให้ export ไฟล์เข้ารหัสและ restore เข้าโปรเจกต์ staging ที่แยกจาก production แล้วตรวจทั้งแถวฐานข้อมูลและไฟล์ Storage
